## 三、文档统一的讲解结构

每个金融概念都按这个固定骨架讲，方便你建立心智模型：

| 段落 | 作用 | 你能拿到什么 |
|------|------|-------------|
| ① **一句话本质** | 用大白话/类比锁定核心 | 一个不会忘的锚点 |

## 四、一个贯穿全文的场景设定

为了不让你被抽象概念绕晕，全文用一个**贯穿场景**：

> **假设你要决定：现在该不该买"苹果公司"(AAPL)？买多少？**
> 系统拿到 `AAPL` 这个代码后，6 个 Agent 会像一家微型投资公司的投委会一样各自表态。
> 所有金融概念都会落在这个场景上讲。

到基金部分，场景会切换成：**该不该买"某只偏股混合型基金"？**

## 五、术语对照（技术人友好）

金融概念我尽量给你一个**技术/工程类比**，帮你锚定：

| 金融概念 | 技术/工程类比 |
|---------|--------------|
| 估值指标(PE/PB) | 性能/价格比（性价比）——同样算力谁更便宜 |
| 技术指标(MACD/RSI) | 监控大盘的 APM 曲线/告警阈值 |
| 风控硬规则 | 生产环境的熔断/限流——确定性、不可绕过 |
| VaR | SLA 里的"99% 请求在 X ms 内"——尾部风险量化 |
| 最大回撤 | 灰度发布时的最大故障半径 |
| 夏普比率 | 性价比 = 收益 ÷ 波动（单位风险换多少收益） |
| 回测 | 上线前的压测/混沌工程——但小心"回测过拟合=压测只测了你准备好的case" |

带着这些类比读，金融就没那么玄了。
