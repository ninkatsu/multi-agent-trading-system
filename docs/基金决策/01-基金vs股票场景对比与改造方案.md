# 基金决策 01 · 基金 vs 股票场景对比与改造方案

> 这是你的最终目标文档。先讲清**基金和股票在这套框架下的所有区别**，再给出**改造蓝图**——把这套"美股股票决策系统"改造成"国内公募基金购买决策系统"。
> 配套背景知识见 `02-基金专属背景知识.md`。

---

## 一、先对齐：基金到底是什么（30秒）

```
   你买股票 = 直接买一家公司的一小块（你是股东）
   你买基金 = 雇一个基金经理，把钱凑一堆，让他替你买一篮子股票/债券
   
   基金净值 = 这一篮子资产的"每股"总价 ÷ 基金总份额
   你赚的钱 = (赎回时净值 − 买入时净值) × 你持有的份额
```

> 一句话：**买基金 = 买"一篮子" + 买"基金经理的选股能力"**。它比单只股票分散、省心，但也有自己的一套规则。

## 二、基金 vs 股票：在本框架下的全量区别

这张大表是核心。**左列是差异维度，中间是股票版现状，右列是基金版要怎么变**。

### 维度1：标的与代码

| | 股票版（现状） | 基金版（改造） |
|---|---|---|
| 标的 | 单只股票 AAPL | 单只公募基金，如 `005827`（易方达蓝筹） |
| 代码体系 | 美股 ticker | 6位基金代码（A类/C类/ETF各有代码） |
| 改造点 | — | 输入从 `AAPL` → `005827`；代码校验逻辑重写 |

### 维度2：基本面（Fundamental Agent）——差异最大

| | 股票版 | 基金版 |
|---|---|---|
| 分析对象 | 一家公司的财报 | 一只基金的"基本面"= 基金经理 + 持仓组合 + 基金公司 |
| 核心指标 | PE/PB/ROE/营收增长 | 基金经理任职年限/历史业绩、重仓股、行业配置、规模、换手率 |
| "值不值"的问法 | 这公司值多少钱 | 这基金经理靠不靠谱、这篮子配得合不合理 |
| 数据源 | yfinance 财报 | akshare/tushare 天天基金接口 |
| **结论** | 基本面 Agent **几乎要重写**，PE/ROE 这些对基金没意义，换成基金专属指标 |

```
   股票基本面：               基金"基本面"：
   PE/PB/ROE/营收/利润        基金经理任期 & 历史年化
   （公司本身好不好）          重仓股清单 & 集中度
                              基金规模 & 是否太大难操作
                              基金公司实力
                              （这基金靠不靠谱）
```

### 维度3：技术面（Technical Agent）——部分复用

| | 股票版 | 基金版 |
|---|---|---|
| 分析对象 | 股票 K 线 | 基金净值曲线（但日频、波动小） |
| 可用指标 | MACD/RSI/布林带/SMA | SMA/均线**可用**；MACD/RSI 对基金净值**意义减弱**（基金净值不像股价那样有强短期动量） |
| 关键差异 | — | **基金一天只有一个净值**（收盘后才公布），没有盘中 K 线；ETF 例外（有盘中价） |
| 改造点 | — | 数据源换；技术指标保留 SMA，MACD/RSI 权重降低；ETF 可沿用股票逻辑 |

> 重点：**普通开放式基金没有实时 K 线**，一天一个净值。技术面能做的有限，更多看"净值趋势 + 相对基准的强弱"。ETF 基金有盘中交易价，可沿用股票技术面。

### 维度4：情绪面（Sentiment Agent）——必改（中文）

| | 股票版 | 基金版 |
|---|---|---|
| 新闻来源 | yfinance 英文新闻 | 天天基金/财经媒体**中文**新闻 |
| NLP 工具 | TextBlob（**中文无效！**） | **必须换**：SnowNLP / 或直接让 GLM 判情绪（中文 LLM 强） |
| 机构持仓 | 看股票的机构持仓 | 看基金的**申赎资金流向**（净申购=受欢迎） |
| 分析师评级 | 股票评级 | 基金评级（晨星星级、天天基金评分） |
| 改造点 | — | TextBlob→GLM情绪判断；数据源全换中文渠道 |

> 这是改造里**最明确必改的点**：TextBlob 是英文情感词典，对中文新闻几乎全输出中性。基金版直接用 GLM 做 zero-shot 情绪判断，又准又省事。

### 维度5：辩论（Debate Agent）——基本复用

| | 股票版 | 基金版 |
|---|---|---|
| 机制 | Bull/Bear/Judge | **完全复用** |
| 改造点 | — | 只改 prompt 里的"股票"→"基金"、指标描述换基金语境 |

辩论机制和标的关系不大，是通用的"对抗性决策"框架——**这是这套系统最可复用的部分**。

### 维度6：风控（Risk Agent）——部分改造

| | 股票版 | 基金版 |
|---|---|---|
| 仓位上限 | 单票≤10% | 单基金≤?（基金本身已分散，可放宽到 20-30%） |
| VaR | 个股历史波动 | 基金净值波动（通常小于个股） |
| 最大回撤 | 8% | 基金回撤阈值要看类型（偏股8-15%、债基2-5%） |
| 止损止盈 | ±5%/+15% | 基金止损意义弱（申赎有费率、净值平滑），更多用"止盈+定投" |
| 流动性 | T+0/T+1 | **普通基金 T+1/T+2 赎回**，到账慢，不能紧急止损 |
| 改造点 | — | 阈值按基金类型重设；加入"申赎费率"成本；T+1 流动性约束 |

> 关键差异：**基金赎回慢（T+1/T+2）+ 有申赎费**，所以"止损"对基金不像股票那么灵敏。基金风控更偏向"仓位管理 + 止盈 + 类型匹配风险偏好"，而非高频止损。

### 维度7：执行（Execution Agent）——重写

| | 股票版 | 基金版 |
|---|---|---|
| 下单方式 | 股票限价单/市价单 | 基金**申购/赎回**（按当天/下一天净值，无"价格"概念） |
| 滑点 | 买卖价差 | **无滑点**，但有**申赎费率**（0~1.5%）作为成本 |
| 成交价 | 实时价 | 当天收盘净值（15:00 前申购按当日净值，之后按次日） |
| 改造点 | — | 完全重写：限价单→申赎单；滑点→费率；时间逻辑按 15:00 切 |

### 维度8：回测（Backtester）——重写数据源

| | 股票版 | 基金版 |
|---|---|---|
| 数据 | yfinance 日 K | akshare 基金净值历史 |
| 基准 | SPY（标普500） | 沪深300 / 中证500 / 对应基金业绩比较基准 |
| 交易成本 | 滑点 | 申赎费 + 管理费摊销 |
| 改造点 | — | 数据源、基准、成本模型全换 |

### 维度9：数据源（基础设施层）——全换

```
   股票版：yfinance（Yahoo，墙内被限流）   ← 你已经踩过这个坑
   基金版：akshare（国内开源，免key，覆盖基金/股票/宏观）  ← 推荐
          或 tushare（需积分，更专业）
          或 天天基金网页接口（akshare 已封装）
   
   → 墙内基金版的巨大优势：数据源全在国内，稳定免费，不再有 yfinance 限流问题！
```

## 四、改造蓝图（分阶段可执行）

### 阶段0：环境（已完成）
- LLM 接 GLM ✓、容错 JSON ✓、yfinance 降级 ✓
- 新增依赖：`akshare`（国内基金/股票数据，免key）

### 阶段1：数据源层替换（最先做）
```
新建 tools/fund_data.py（仿 market_data.py）：
  - get_fund_nav(code)          历史净值
  - get_fund_info(code)         基金信息（经理/规模/类型/费率）
  - get_fund_holdings(code)     重仓股
  - get_fund_manager(code)      基金经理历史业绩
  - get_fund_flow(code)         申赎资金流向
全部用 akshare，国内直连，告别 yfinance 限流。
```

### 阶段2：基本面 Agent 重写
```
FundamentalAgent → FundQualityAgent
指标换成：
  - 基金经理任期 >3年 & 历史年化 >15%  → +2
  - 重仓股集中度（前10占比）适中 50-70% → +1，>90%太集中 -1
  - 基金规模 10亿-200亿（适中好操作）→ +1，>500亿太大难跑赢 -1
  - 基金公司实力（头部）→ +1
  - 换手率（适中）→ 0
评分体系 1-10 不变，下游接口不变。
```

### 阶段3：情绪面 Agent 重写（中文 NLP）
```
_textblob → GLM 直接判情绪：
  把新闻标题列表喂给 GLM，prompt 让它输出 {"sentiment": -1~+1, "reasoning": ...}
  中文新闻用 GLM 比 TextBlob 准一个量级。
机构持仓 → 申赎资金流向（净申购为正=受欢迎）
分析师评级 → 晨星星级 / 天天基金评分
```

### 阶段4：技术面 Agent 适配
```
ETF 基金：沿用股票 K 线逻辑（有盘中价），数据源换 akshare ETF 接口
普通基金：用净值曲线，保留 SMA/均线，MACD/RSI 权重降低
  - 净值在均线之上且均线上行 → +2
  - 净值创新高/突破平台 → +1
```

### 阶段5：Risk + Execute 改造
```
Risk:
  - 仓位上限按基金类型：偏股混合 25%、指数 30%、债基 50%
  - 回撤阈值按类型：偏股 12%、债基 4%
  - 新增"申赎费率"成本检查
  - T+1 流动性提醒（不能像股票那样紧急止损）
Execute:
  - 重写为申购/赎回单
  - 15:00 前申赎按当日净值，之后按次日
  - 滑点模型 → 费率模型（申购费0~1.5%、赎回费按持有期递减）
  - dry_run 输出"[模拟] 申购 005827 ¥100000 @ 净值2.345，申购费¥150"
```

### 阶段6：回测改造
```
数据：akshare 基金净值
基准：换成对应业绩比较基准（如沪深300）
成本：申赎费 + 管理费年化摊销
信号：可用简化规则（净值上穿均线+资金净申购→BUY）
```

## 五、一个具体场景：用改造后的系统决定"该不该买 005827"

```
输入：005827（易方达蓝筹精选混合）

① 基本面 Agent（重写后）：
   基金经理张坤，任期8年，历史年化14% (+2)
   重仓白酒+港股，集中度85%（偏高 -1）
   规模400亿（偏大 -1）
   → 评分 6，HOLD（"好经理但规模太大、太集中"）

② 技术面 Agent：
   净值在 60 日线上方，均线多头 (+2)
   但近 3 月跑输沪深300 (-1)
   → 评分 6，HOLD

③ 情绪面 Agent（GLM 中文）：
   新闻：白酒板块承压、北向资金流出 → GLM 判情绪 -0.4 (负面 -1)
   申赎：近 3 月净赎回（资金在撤 -2）
   评级：晨星 4 星 (0)
   → 评分 3，SELL

④ 辩论：
   Bull："张坤是顶级经理，长期年化14%，白酒回调是机会"
   Bear："规模太大难跑赢、重仓白酒太集中、资金在撤、近期跑输基准"
   Judge："HOLD，置信度0.6，若买建议小仓位5%，等白酒企稳"

⑤ 风控：
   硬规则：5%仓位<25%上限 ✓、回撤4%<12%限 ✓ → 过
   LLM："白酒处于下行+资金撤，建议否决或降到2%"
   → approved=False → Reject

⑥ 执行：今日不申购。记录"等待白酒企稳+资金回流再评估"
```

> 这个流程和你做美股 AAPL 时**结构完全一致**，只是每个节点的"金融内核"换成了基金语境。**这就是框架的价值——拓扑复用，内核替换**。

## 六、给你的工程建议（优先级）

```
P0（先做，解锁一切）：数据源层 tools/fund_data.py 用 akshare
P1（最大价值）：基本面 + 情绪面 Agent 重写（这俩决定基金决策质量）
P2（必改）：执行 Agent 改申赎单 + Risk 加费率/T+1
P3（锦上添花）：回测用基金净值 + 中文基准
可不动：trading_graph、LLM工厂、容错JSON、Debate机制
```

**关键技术红利**：
1. 基金数据源在国内（akshare），**彻底解决你已踩过的 yfinance 墙内限流坑**。
2. 情绪面用 GLM 直接判中文，**比 TextBlob 准且零额外依赖**。
3. 编排层零改动，**你已熟悉的 LangGraph 拓扑全部复用**。
