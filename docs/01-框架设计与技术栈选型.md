# 01 · 框架设计与技术栈选型

> 技术部分给你从简但点到为止——你是 agent 专家，这里只讲**这套系统怎么搭、为什么这么搭、哪些设计值得偷师**。代码全部以 Python 版为准。

---

## 一、一句话定位

> 一个**用 LangGraph 编排的 6-Agent 投资决策流水线**：输入一个股票代码，模拟一家投资公司的"分析师团队 → 牛熊辩论 → 风控审批 → 下单执行"全流程，输出"买/不买/买多少"。

它不是"一个万能大模型一把梭"，而是**把投资决策拆成 6 个专职角色，用图编排强制走流程**——这本身就是值得学的架构思想。

## 二、技术栈一张图

```
┌─────────────────────────────────────────────────────────────┐
│                       应用层                                 │
│   graph/trading_graph.py  ← LangGraph StateGraph 编排        │
├─────────────────────────────────────────────────────────────┤
│                       Agent 层（6 个）                        │
│   fundamental / technical / sentiment / debate / risk / exec │
│   每个 Agent = 数据获取 + LLM 研判 + 结构化输出              │
├─────────────────────────────────────────────────────────────┤
│                       能力层                                 │

│   numpy/pandas(数值)  python-dotenv(配置)  pydantic(校验)    │
└─────────────────────────────────────────────────────────────┘
```

## 三、技术栈选型：为什么是这些

| 层 | 选型 | 为什么选它 | 替代方案（项目里没用） |
|----|------|-----------|----------------------|
| 编排 | **LangGraph** | 状态图 + 并行 + 条件边 + 检查点，比裸写 async 控制流更可声明、可回放 | AutoGen(对话式)、CrewAI(角色化)、裸 asyncio |
| LLM 抽象 | **LangChain ChatModel** | 统一 `invoke([messages])` 接口，换 provider 不动业务 | 直接调 SDK |
| 行情数据 | **yfinance** | 免费、免 key、覆盖全球股票 | Tushare/Akshare(国内)、Alpha Vantage |
| 技术指标 | **pandas_ta** | 纯 Python，`df.ta.macd()` 一行算好，无需编译 | TA-Lib(C 扩展, 装起来痛) |
| 情绪 NLP | **TextBlob** | 极简情感极性，`blob.sentiment.polarity` 出 -1~+1 | VADER、LLM 直接判 |
| 配置 | **dotenv + dataclass** | 集中、类型清晰、frozen 不可变 | pydantic-settings（更重） |

### 值得偷师的选型判断

```
"指标计算为什么用 pandas_ta 不用 TA-Lib？"
   └─ TA-Lib 是 C 扩展，Windows 装包经常失败；pandas_ta 纯 Python，pip 即装。
      对于"学习/面试项目"这种场景，安装零障碍 > 极致性能。这是很务实的工程取舍。

"情绪为什么用 TextBlob 这种老工具，不直接让 LLM 判？"
   └─ 原项目用 TextBlob 做基础极性，省 token、确定性高。
      但在你后续的基金改造里，新闻是中文的，TextBlob 对中文几乎无效——
      这正是改造点之一（见 基金决策/01）。
```

**结构上的设计纪律**（值得学）：
- **Agent / 编排 / 工具 三层分离**：Agent 只管"研判"，编排只管"流程"，工具只管"取数/算数"。换数据源不动 Agent，换 Agent 不动编排。
- **每个 Agent 一个文件 + 一个 dataclass 结果类型**：`FundamentalAnalysis`、`TechnicalAnalysis`… 强类型契约，下游不用猜字段。
- **配置全部走环境变量**：没有硬编码 key，`.env` 一份搞定，`.env.example` 是契约。

## 五、Agent 内部的统一三段式骨架

6 个 Agent 虽然职责不同，但**内部结构高度同构**——这是一个可以复用的"Agent 模板"：

```
┌─────────────────────────────────────────────────┐
│  Agent.run(state)         ← LangGraph 节点入口   │
│    └─ analyze(ticker)                           │
│         ① fetch/compute  ← 取数/算指标（确定性） │
│         ② 构造 prompt     ← 把数据塞进模板       │
│         ③ llm.invoke      ← LLM 研判            │
│         ④ parse_json_loose← 容错解析结构化结果   │
│         ⑤ 组装 dataclass  ← 强类型返回           │
└─────────────────────────────────────────────────┘
```

对应代码（以 fundamental_agent 为例，已做墙内改造）：

```python
# ① 取数 —— 防御性：yfinance 限流就返回空，不让单点故障拖垮整张图
def fetch_fundamentals(self, ticker):
    try:
        info = yf.Ticker(ticker).info or {}
    except Exception:
        return {}
    return {"pe_ratio": info.get("trailingPE"), "roe": info.get("returnOnEquity"), ...}

def analyze(self, ticker):
    fundamentals = self.fetch_fundamentals(ticker)          # ①
    user_prompt = f"请分析 {ticker} 的基本面：PE={...}..."    # ②
    response = self.llm.invoke([                            # ③
        SystemMessage(content=self.SYSTEM_PROMPT),
        HumanMessage(content=user_prompt),
    ])
    result = parse_json_loose(response.content) or {         # ④ 容错解析
        "score": 5.0, "signal": "HOLD", "reasoning": "解析失败默认HOLD"
    }
    return FundamentalAnalysis(ticker=ticker, ...,           # ⑤
                               score=result.get("score", 5.0),
                               signal=result.get("signal", "HOLD"))
```

> **为什么要强调这个骨架？** 因为你改造基金版时，不需要重新发明 Agent——只要把 ①取数 换成基金数据源、②prompt 换成基金语境，③④⑤ 全部复用。这是这套框架给你最大的杠杆。

## 六、状态在 Agent 间怎么流动（reducer 机制）

LangGraph 的核心机制之一，值得单独点出：

```python
class TradingState(TypedDict):
    ticker: str
    analyses: Annotated[list[dict], operator.add]   # ← 关键
    debate_result: dict
    risk_assessment: dict
    execution_result: dict
    ...
```

`Annotated[list, operator.add]` 是 **reducer**：当 3 个并行分析 Agent **同时**往 `analyses` 写结果时，LangGraph 不是"后写覆盖先写"，而是**自动 `+`（list 拼接）**。这就是 Fan-in 的底层保证——你不用自己写锁/队列。

```
   fundamental.run ─┐
   technical.run   ─┼─→ analyses = [..fund..] + [..tech..] + [..sent..]  ← reducer 自动合并
   sentiment.run   ─┘
                          │
                          ▼
                     debate.run(state)  ← 拿到完整 3 份分析
```

技术类比：这就是 map-reduce 里的 reduce，或 React 里多个 setState 用函数式更新避免覆盖——**并发写共享状态要用 reducer 而非直接赋值**。

## 七、条件路由：一票否决怎么落到图上

```python
def should_execute(state) -> str:
    return "execute" if state["risk_assessment"].get("approved") else "reject"

graph.add_conditional_edges("risk", should_execute,
                            {"execute": "execute", "reject": "reject"})
```

```
        risk 节点
       approved?
      /         \
   True        False
     ↓           ↓
 execute       reject ─→ END（不下单）
     ↓
   END（下单）
```

技术类比：这就是工作流引擎里的**网关（gateway）**，或代码里的 `if/else`——但它是**声明在图拓扑上**的，可可视化、可回放、可审计。金融场景里这种"硬门控"尤其重要（见 02 和 金融背景/04）。

## 八、墙内运行改造点速查（已为你做好）

| 改造 | 文件 | 解决什么 |
|------|------|---------|
| LLM 工厂接 GLM | `config/llm.py`（新增） | 用智谱 Anthropic 兼容端点，国内直连 |
| 容错 JSON 解析 | `config/json_utils.py`（新增） | GLM 偶尔把 JSON 包 ```json 围栏，原生 `json.loads` 会挂 |
| 5 个 Agent 接工厂 | `agents/*.py` | 去掉硬编码 `ChatOpenAI`，统一 `get_llm()` |
| yfinance 防御性降级 | `agents/*.py` 各取数点 | 限流/超时不崩图，回退默认值继续走流程 |
| 移除 alpaca-trade-api | `requirements.txt` | 老库拉旧 msgpack 要源码编译，被 WDAC 策略挡；dry_run 不需要它 |

**已验证可跑**：`python -m graph.trading_graph`（输入 AAPL），完整 6 Agent 流水线在 GLM 上端到端跑通（约 90s，yfinance 被限流时自动降级为 HOLD 决策，不报错）。
