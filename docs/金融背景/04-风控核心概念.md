# 金融背景 04 · 风控核心概念

> Risk Agent 看这些。**这是整个系统最重要的安全底线**。前面 5 个 Agent 都在研究"怎么赚钱"，风控研究的是"**怎么不亏死**"。
> 投资第一铁律：**先活下来，再谈赚钱**。固定结构讲解。

---

## 大图：风控在守什么

```
                  "怎么确保一次错判不会要命？"
                          │
        ┌─────────────────┼─────────────────┐
        ▼                 ▼                 ▼
   【单次损失控制】    【组合损失控制】    【进出成本控制】
   仓位上限           VaR 风险价值         滑点
   止损 / 止盈         最大回撤             （下单时的价差损耗）
        │                 │                 │
        └─────────────────┼─────────────────┘
                          ▼
          底线用【硬规则代码】焊死，LLM 只做软增强
                  （一票否决权）
```

> 一句话：**风控 = 限制单次冒险的破坏半径 + 量化"最坏情况亏多少" + 给退出设好自动阀门。**

---

## 概念1：仓位（Position Size）——破坏半径

**①一句话本质**：这一笔投进去的钱，占总资金的比例。**仓位 = 你愿意为这次判断赔上多少**。

**②图**：
```
   总资金 $1,000,000
   ┌─────────────────────────────────────────┐
   │■■■ 10%  │                              │
   │  AAPL   │   其余 90% 是安全垫           │
   └─────────────────────────────────────────┘
   
   仓位 10% → 即使 AAPL 跌 50%，总资金也只亏 5%，能承受
   仓位 50% → 同样跌 50%，总资金亏 25%，重伤
   仓位 100%→ 同样跌 50%，腰斩，可能再也回不来
```

**③场景**：你有 100 万，对苹果很有信心。满仓 100 万买苹果 → 一只股票黑天鹅（库克离职/反垄断重罚）你就亏几十万。限仓 10%（10 万）→ 同样的事故你只亏几万，活得好好的等下一次机会。**限仓就是把"单次错判的代价"控制在可恢复范围**。

**④本项目用法**（硬规则，不可绕过）：
```
MAX_POSITION_SIZE = 0.1   # 单票仓位上限 10%
if proposed_position > 0.1: REJECT   # 超 10% 直接否决，不问 LLM
```

**⑤陷阱**：仓位不是越低越好——太低赚不到钱。**关键是和"信心+胜率"匹配**：高置信度可适当提高，低置信度必须小仓。这正是 Debate 输出的 `confidence` 影响 `target_position_pct` 的逻辑。

> 技术类比：仓位 = 限流阈值 / 单请求超时时间——设太大一次故障拖垮全系统，设太小吞吐量上不去。要按"故障半径"设。

## 概念2：止损 / 止盈（Stop Loss / Take Profit）——自动阀门

**①一句话本质**：提前定好"亏到多少自动砍仓"和"赚到多少自动落袋"，**用规则代替情绪**。

**②图**：
```
   买入价 $200
        │
   止盈 $230 ( +15% )  ────  赚够了，自动卖，锁利润
        ↑
        │  持有区间
        ↓
   止损 $190 ( -5% )   ────  亏到线，自动砍，认错出场
   
   为什么"自动"这么重要？
   因为人是"亏了不甘心卖、赚了还想赚更多"的动物，
   没有阀门就会从小亏熬成大亏、从大赚熬成小赚。
```

**③场景**：苹果 $200 买入，设止损 $190、止盈 $230。后来苹果跌到 $189 → 系统自动卖出，亏损锁定在 5%。如果没有止损，你可能"再等等看"，结果跌到 $170，亏 15%。**止损的本质是"承认判断会错，并提前设好认错线"**。

**④本项目用法**：
```python
stop_loss  = 现价 × (1 - 0.05)   # 亏5%止损
take_profit = 现价 × (1 + 0.15)  # 赚15%止盈
```

**⑤陷阱**：
- **止损太紧会被"洗出去"**：设 2% 止损，正常波动就触发，频繁小亏累计成大亏。止损要放在"正常波动之外"（结合 ATR/布林带宽度）。
- **止损后可能反弹**：止损是"控制损失"不是"判断方向"，砍在低点反弹是常态，别因此不设止损。

## 概念3：VaR（Value at Risk，风险价值）——最坏情况量化

**①一句话本质**：在"倒霉但不极端"的情况下（比如 95% 置信度），**一天最多亏百分之几**。

**②公式 + 图**（本项目用历史模拟法）：
```
   取过去一年每日收益率 → 排序 → 取第 5% 分位（最倒霉的那 5% 的边界）
   
   例：苹果历史日收益分布，第5分位是 -3%
   → VaR(95%) = 3% → "95% 的情况下，一天最多亏 3%"
   → 还有 5% 的更倒霉日子会亏超过 3%（尾部风险）
```

```
   日收益分布（简化）：
   
   频次
    │     ╱╲
    │    ╱  ╲
    │   ╱    ╲
    │  ╱      ╲
    │ ╱        ╲___ 
    │/    |         ╲___  ← 尾部：5%的倒霉日子，亏超3%
    └─────┼──────────→ 收益率
         -3%         0%
          ↑
       VaR(95%)=3%
       "95%概率下，最多亏到这"
```

**③场景**：组合 100 万，苹果 VaR 5%、仓位 10% → 这笔持仓的 VaR 敞口 = 5% × 10% = 0.5% 的总资金 = $5000。"正常倒霉一天最多亏 5000，能接受。"若仓位 50% → 敞口 2.5% = $25000，超限，风控否决。

**④本项目用法**（硬规则）：
```python
var = np.percentile(日收益, 5)          # 历史第5分位
if var * proposed_position > 0.02:      # 敞口超组合2%
    REJECT                               # 否决
```

**⑤陷阱**：
- **VaR 只管 95%，不管那 5% 的尾巴有多长**——它告诉你"最多亏到这"，但极端黑天鹅（5%里的 1%）可能亏远超 VaR。所以还要看"条件 VaR/CVaR"（尾部平均）。
- **历史不代表未来**：基于过去波动算的，遇到前所未有的事件（如疫情）会失真。VaR 是参考线不是保险。

> 技术类比：VaR 像 SLA 的"99% 请求在 200ms 内"——它承诺的是常规情况，不承诺尾部；真正极端故障要看 P99/P999。金融里 VaR=95%分位，CVaR 才是真正的尾部。

## 概念4：最大回撤（Maximum Drawdown）——痛感指标

**①一句话本质**：从历史最高点到之后最低点，**最多跌了多少**。衡量"持有期间最痛的时刻"。

**②公式 + 图**：
```
   最大回撤 = (峰值 − 谷值) ÷ 峰值

   净值
    │   ╱╲ 峰值
    │  ╱  ╲        ╱╲
    │ ╱    ╲      ╱  ╲ ← 又创新高，回撤结束
    │╱      ╲    ╱
    │        ╲  ╱
    │         ╲╱ 谷值
    │   ←─────→
    │     这段就是最大回撤（峰值到谷值的跌幅）
    └────────────── 时间
```

**③场景**：策略净值从 1.0 涨到 1.2（峰值），又跌到 1.05（谷值）→ 最大回撤 = (1.2−1.05)/1.2 = 12.5%。意思是"最惨的时候，你比最高点少了 12.5%"。**同样年化收益，回撤越小越好**——因为大回撤会击穿心理防线让你割在低点。

**④本项目用法**：
```
MAX_DRAWDOWN_LIMIT = 0.08   # 组合回撤超 8% 否决新开仓
peak = 净值.expanding().max()
drawdown = (净值 - peak) / peak
max_drawdown = abs(drawdown.min())
```

**⑤陷阱**：最大回撤是"已发生"的最深跌幅，不代表未来不会更深。8% 的回撤限制本质是"已经伤成这样了，别再加风险"的熔断。

## 概念5：滑点（Slippage）——隐藏成本

**①一句话本质**：你下单时的价格，和实际成交价格之间的差。**你以为买在 $200，实际成交在 $200.4，多付的 0.4 就是滑点**。

**②为什么会发生**：
```
   你下单买 10000 股，但当前卖一档只有 1000 股挂 $200
   → 吃完卖一档，剩下 9000 股要买更贵的卖二档 $200.3、卖三档 $200.5...
   → 平均成交价 $200.4，比你看到的价格高 0.2%
   
   买得越多、流动性越差 → 滑点越大
```

**③场景**：你看苹果 $200，市价单买入 10000 股，结果成交均价 $200.5 → 多花了 $5000，这就是滑点损失。**大资金最怕滑点**——一笔大单能把价格自己顶上去。

**④本项目用法**（限价单控滑点）：
```python
def _calculate_limit_price(current_price, side, slippage_tolerance=0.002):
    if side == "buy":
        return current_price * (1 + 0.002)   # 最多多付0.2%，挂限价
    return current_price * (1 - 0.002)        # 卖出最少卖到这
```
"买入时挂略高于市价的限价单"——宁可少买，不在烂价格成交。

**⑤陷阱**：限价单控了滑点，但可能"成交不了"（价格跑了你没买到）。**控滑点 vs 保证成交是跷跷板**——市价单保证成交但滑点大，限价单控滑点但可能漏单。

## 概念6 & 7：夏普比率 / 索提诺比率——性价比（回测也用）

**①一句话本质**：**每承担 1 单位风险，换来多少超额收益**。收益高不算本事，风险调整后收益高才是。

**②公式 + 图**：
```
   夏普 = (年化收益 − 无风险利率) ÷ 年化波动率
   
           收益                   收益
            │  A (高收益高波动)     │   B (中收益低波动)
            │  ╱                   │   ╱
            │ ╱                    │  ╱
            │╱                     │ ╱  ← 夏普更高！
            └──── 波动              │╱
                                   └──── 波动
   
   A 收益 20% 波动 20% → 夏普 (20-4)/20 = 0.8
   B 收益 12% 波动 6%  → 夏普 (12-4)/6  = 1.33  ← 性价比更高
   
   索提诺 = 分母只算"下行波动"（亏损的波动），上涨的波动不算坏事
   → 索提诺 ≥ 夏普，对"赚得多但偶尔大亏"的策略更苛刻
```

**③场景**：策略 A 年化 30% 但大起大落（夏普 0.9），策略 B 年化 15% 但稳如老狗（夏普 2.0）。理性人选 B——A 那种大波动你拿不住，中途会割肉；B 才睡得着拿得住。**夏普 >1 算好，>2 优秀**。

**④本项目用法**：回测时计算，作为策略好坏的核心评价。

**⑤陷阱**：
- 夏普假设收益正态分布，**低估尾部风险**（黑天鹅）——所以要看索提诺和最大回撤一起。
- 高夏普可能是"过拟合"出来的（见回测陷阱）。

> 技术类比：夏普 = 性能/成本比。只看收益（吞吐）不看波动（延迟方差）是耍流氓——一个 P99 抖到天上去的服务，平均吞吐再高也没法用。

## 双层门控总图（项目核心设计）

```
   辩论结论 (BUY, 仓位30%)
            │
   ┌────────▼────────────────────────────────┐
   │ 第一层：硬规则（确定性代码，不可绕过）   │
   │                                          │
   │  ① 仓位 30% > 10%上限     → 违规!        │
   │  ② 组合回撤 9% > 8%限制   → 违规!        │
   │  ③ VaR敞口 2.5% > 2%限制  → 违规!        │
   │                                          │
   │  任一违规 → 直接 REJECT，根本不问 LLM    │
   └────────┬────────────────────────────────┘
            │ 全部通过
   ┌────────▼────────────────────────────────┐
   │ 第二层：LLM 软判断（处理模糊情况）       │
   │                                          │
   │  "市场今天恐慌性暴跌，虽然规则都过，     │
   │   但建议仓位从30%降到5%，或直接否决"     │
   │                                          │
   │  → 可建议降仓 / 否决（approved=false）   │
   └────────┬────────────────────────────────┘
            │ approved?
       True │ False
            ▼
        Execute    Reject
```

**这个双层设计的金融+工程双重意义**：
```
金融意义：硬规则保证"数学上不可能超限"，LLM 补"规则没覆盖的情境判断"
工程意义：确定性兜底 + LLM 增强，和"限流熔断 + 智能调度"同构
安全意义：LLM 可被注入/幻觉，但翻不过 if 仓位>0.1 这道数学墙
```

## 总览表

| 概念 | 本质 | 本项目阈值 | 陷阱 |
|------|------|-----------|------|
| 仓位 | 单次破坏半径 | ≤10%/票 | 太低赚不到，要匹配置信度 |
| 止损/止盈 | 自动认错/落袋阀 | -5%/+15% | 太紧被洗出，设太松没用 |
| VaR | 95%倒霉日最大亏 | 敞口≤2% | 只管95%不管尾部 |
| 最大回撤 | 最痛时刻跌幅 | ≤8% | 历史不代表未来 |
| 滑点 | 下单隐藏成本 | 限价±0.2% | 控滑点vs保证成交跷跷板 |
| 夏普 | 风险调整后收益 | >1好>2优 | 低估尾部、可能过拟合 |
| 索提诺 | 只算下行风险的夏普 | ≥夏普 | 同上 |

## 一句话串起来（场景复盘）

> 苹果辩论结论"BUY 30%仓位"，进风控：
> - 硬规则①：30% > 10%上限 → **违规，直接否决**。根本轮不到 LLM 说话。
> - 假设仓位被 Debate 自己降到 8%：硬规则全过 → LLM 软判断"市场恐贪指数 80 偏贪婪，建议降到 3% 或否决"→ approved=False → Reject。
>
> → 这就是为什么最终执行常常是 NO_ACTION/RISK_REJECTED：**风控是故意设计成"宁可错杀不可漏判"的**。在金融里，少赚可以接受，爆仓不能接受。
